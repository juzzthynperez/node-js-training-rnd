## Process notes (binding for M08+)

- **Contract-fidelity review is now a required pre-PR step for any layer swap**, not just a
  suite run: diff the old layer's *behavior* against the new one case-by-case (error
  precedence, empty-value rendering, response shapes, headers), then classify each difference
  as restore-or-document. M08 (Zod replacing `validation.ts`) is exactly this shape — v1's
  validator semantics ARE the contract, tests or not.
- **Reviewer claims get evidence tiers.** Fix claims verified empirically before acting (two
  of fourteen findings were wrong on inspection and both were settled with one command each);
  keep the "live-verify everything you review" standard the `general` agent used — it is what
  made the remaining findings trustworthy.
- **Config and version questions are answered from installed artifacts** (`.d.ts` shapes, CLI
  output, actual DB state), never from remembered docs. "The type file is the spec" held again:
  `MigrationsConfigShape.seed` placement was right; the *behavior* had moved.
- **Schema era + migration history move as one unit.** Any future history surgery (M09's
  `test.db` experiments are the likely next candidate) replays eras by moving both or neither,
  and never asks a non-interactive shell an interactive question.
- **Native dep pins are part of the environment contract:** direct versions of anything with a
  native binding must land inside the dependent library's declared range; `npm ls <pkg>` +
  a require-test go in the versions evidence, after every install change.
- **The consent env var belongs in CI notes:** any pipeline step running `migrate reset`
  from an agent context must carry `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` or the step
  hangs/fails — humans get a prompt, automation gets a wall.
- **Seeded identity is a cross-file contract:** constants that data must match
  (`DEFAULT_OWNER_ID`) are imported by both sides and named in comments both ways; M09's
  test fixtures inherit this (fixed ids make assertions possible).
- **The Mermaid render gate now has a settled harness shape** (confirmed in VALIDATE): the
  session's browser tool refuses `file://` URLs, so serve the harness page from a tiny node
  http server on `localhost` (background); headless Chrome's `--screenshot` flag wrote no file
  in this environment, so the proof is `--headless=new --dump-dom` **with
  `--virtual-time-budget`** (without it Chrome dumps before the CDN module import resolves)
  — page title flipped to a success marker *inside* `mermaid.render`'s success path, plus
  `<svg>` counted in the serialized DOM. Capture honestly: if no PNG exists, the evidence file
  says DOM-dump, not screenshot.
