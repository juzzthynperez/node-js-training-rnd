## Bugs and drift the artifacts caught

1. **Bare pipeline isn't optional inside `z.object`** — every *absent* query param came back
   `expected nonoptional, received undefined`; even queryless `GET /tasks` 400'd (5 of the 6
   first-run failures). The standalone field probe said the pipeline accepted `undefined`; the
   object's view of it said otherwise. Fix: outer `.optional()`, commented at the call site.
2. **`.partial()` over `.default("todo")` resurrected the default** — `PATCH {}` parsed as
   `{status:"todo"}`, satisfied the cross-field refine, answered **200 instead of 400** (the
   6th failure). Fix: both schemas derive from a default-free base; create alone adds the
   default.
3. **Message-unification drift (self-inflicted, caught pre-BRuno by the literal diff):** the
   shared field vocabulary collapsed m07's context-specific PATCH wording (`Must be a non-empty
   string` / `Must be a string`) into create's. No Bruno test asserts these strings — the
   check that found them was grepping m07's deleted validator for message literals and diffing.
   Fix: `taskFields({title, description})` factory parameterized by context message — one logic,
   byte-identical wire.
4. **Zod 4.6.7 crashes on `{ error: { message } }` for `.refine()`** — found by the planned
   probe script (zod4-probe.ts) *before* any schema existed; string and legacy forms survive.
5. **Material gate-4 recipe drift (caught in this VALIDATE):** §9's removal-gate block listed
   `grep 'req\.(body|query)' src/routes` and claimed zero matches, but two *comment* lines in
   `task-handlers.ts` match it — the evidence file's actual gate excludes comment lines. Fixed
   in the material (filter added, comment-carve-out explained); the evidence file was correct
   all along.
6. **Pre-PR review, HIGH — object `.refine()` runs even after strict failure:** `PATCH
   {"foo":1}` collected the unknown-key detail *and* a spurious `"At least one of …"`. Zod 4
   runs the refinement against the *dirty* parsed value; m07 made the classes mutually
   exclusive (`if (errors.length > 0) return { errors }` sat before the emptiness check). No
   Bruno request asserted the difference — and worse, the /apply envelope capture had
   *labeled* the two-detail output "m07 parity" without ever running m07's validator on that
   input. Fixed: the cross-field rule became a pre-parse guard
   (`unknown().refine(nonempty).pipe(object.partial().strict())`), restoring the exclusivity
   and m07's array/non-object handling.
7. **Pre-PR review, five smaller drifts (all fixed in `887ecb8`):** mixed-body detail
   ordering (Zod shape-first vs m07 unknown-first — mapper now sorts unknown-key details
   first); `z.coerce.number()` accepting `007`/`1e3`/`+1`/`0x10` as 200 where m07's
   `/^[1-9][0-9]*$/` said 400 (string gate before coercion, incl. `Number.isSafeInteger`
   parity — 33rd-case sanity now pins both); create `status: null` 400 vs m07's `??`
   default (preprocess null→undefined); `z.uuid()` enforcing RFC version/variant nibbles
   m07's hex regex didn't (exact regex restored); `validate()` body-before-params vs m07's
   id-first precedence (params→query→body). Accepted as-is, documented: `NODE_ENV` enum
   fail-fast (deliberate tightening) and the `^4.6.7` caret (lockfile pins 4.6.7).

## Process notes (binding for M09+)

- **Probe compositions, not components.** Standing probe cases for any schema work: *absent key
  inside the object*, *empty object through the derived schema*, *repeated key*, *non-object
  body* — the shapes real traffic produces. Bugs 1 and 2 were invisible to leaf-level probes and
  fatal to the suite.
- **The message-literal parity diff runs BEFORE schema writing, as a spec input** — grep the old
  layer's frozen strings out, diff against the new layer's, decide each one restore-or-document.
  The green suite asserts a subset; the remainder is where "cleanup" silently changes the wire.
- **Logic may be shared; wording is contract.** Parameterize a shared field factory by its
  context message when the old layer froze per-context strings — single-source rules without a
  wire change.
- **String-form `error` param only** on zod 4.6.x (object form crashes on `.refine()`); the
  version-API probe habit from M07 now extends to library surfaces, not just CLI behavior.
- **`db:deploy` + `db:seed` is the reset's non-destructive twin** whenever recorded history is
  complete — consent-free under Prisma's AI guard, reviewable, and identical on an empty db.
  Reset (with explicit consent) is reserved for rewriting history.
- **Verbatim owner text survives compaction in `opencode.db`** — `session_message.data` holds
  the full JSON with the message text; query it (better-sqlite3, readonly) instead of guessing
  or re-asking when a char-identical gate needs the original.
- **Validate-time re-verification is cheap and earned its keep**: the fresh gate runs are what
  surfaced bug 5 (the material would have shipped a recipe that fails on its own repo).
- **A capture labeled "parity" is not parity — diff the OLD layer's actual behavior.** The
  /apply envelope capture asserted m07 ordering for `PATCH {"foo":1}` without running m07's
  validator on that input; the pre-PR review did, empirically, against the real functions (a
  pure-function diff is nearly free) and found the claim false. For every layer swap, feed
  identical inputs through old and new and diff outputs, per case — the green suite and
  message-literal diff are floors, not proof.
- **The pre-PR review earned its keep as a standing step:** 6 wire drifts that no suite
  asserted, found for the cost of one subagent run with fresh eyes — and two of them were
  *my own mislabels*, invisible from inside the cycle. Run it after /validate and before
  push, every module, regardless of how green the evidence looks.
